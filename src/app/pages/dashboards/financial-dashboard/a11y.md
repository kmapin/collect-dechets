# Accessibilité — Financial Dashboard (Prompt 16)

Checklist de ce qui a été implémenté et de ce qui reste à vérifier manuellement (aucun
outil d'audit automatisé — axe/Lighthouse — n'a été exécuté dans cette session).

## Fait

- **Statut jamais porté par la seule couleur** : chaque badge (`shared/status-badge`)
  combine icône + texte + couleur (Actif/Inactif, À jour/N mois de retard, Payée/Impayée).
- **Squelettes de chargement** au format de la mise en page finale (cartes KPI, lignes de
  tableau, blocs graphique) — pas de saut de mise en page à l'arrivée des données.
- **`prefers-reduced-motion`** respecté partout où une animation de squelette existe
  (`animation: none` en substitution).
- **Palette de graphiques** Okabe-Ito (daltonien-safe) — `shared/chart/chart-palette.util.ts`.
- **Repli tableau accessible** pour les 3 graphiques (`<details><table>` avec les mêmes
  données que le canvas, `role="img"` + `aria-label` sur le canvas).
- **Navigation par onglets** : `role="tablist"/"tab"` + `aria-selected` réactif sur
  finance-layout (nav principale), client-sheet (Info/Facturation) et client-list
  (filtre de statut).
- **Focus visible** (`:focus-visible` avec contour 2px) sur tous les éléments interactifs
  custom (onglets, boutons, filtres, role-switcher, panneau démo).
- **Cibles tactiles** : hauteur minimale ~36px sur les cellules de tableau en vue carte
  mobile (`styles/_responsive.scss`), boutons avec padding généreux.
- **Tableaux → cartes** sur petit écran (<640px) via `data-label` + le mixin partagé
  `table-to-cards` — évite le défilement horizontal illisible sur mobile.
- **États vides/erreurs explicites et contextuels** (français, spécifiques à l'écran),
  jamais un tableau simplement vide sans message.
- **Impression** : le relevé (F10) masque le chrome de l'app et les contrôles non
  pertinents (`.no-print`), typographie resserrée pour le papier.
